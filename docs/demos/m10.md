# M10 demo — billing, gating and launch

```bash
pnpm --filter @pencil/web test       # webhook handler: per-deal, pro, renewal, cancellation, duplicates
pnpm --filter @pencil/web test:e2e   # e2e/billing.spec.ts runs against a Free-tier server
scripts/restore-drill.sh             # backup and restore rehearsal (needs PostgreSQL binaries)
```

Free-tier gating by hand:

```bash
pnpm --filter @pencil/web build
cd apps/web
PENCIL_DEV_AUTH=1 PENCIL_DEFAULT_TIER=free STRIPE_WEBHOOK_SECRET=whsec_demo AUTH_SECRET=dev \
  DATABASE_URL=pglite://./.data/demo-free pnpm start -p 3000
```

1. Sign in, create a deal, open *Package*: the export buttons are disabled and the upgrade prompt
   offers *Unlock this deal · $199 once* and *Go Pro · $2,400 / year*. Without Stripe keys the
   buttons explain that billing is not configured; with `STRIPE_SECRET_KEY` and the two price ids
   they open Stripe Checkout and return to the Package screen.
2. *Settings* shows the tier, the active entitlements, the purchase buttons, *Manage billing* once
   a purchase exists, and the organization id to quote to support.
3. Simulate the purchase (what Stripe sends after Checkout) — sign the payload with the webhook
   secret and post it; `apps/web/e2e/billing.spec.ts` has the signing helper:

   ```bash
   stripe listen --forward-to localhost:3000/api/billing/webhook   # with the Stripe CLI
   ```

   Reload the Package screen: the prompt is gone and *Export Excel* produces Version 1. A second
   delivery of the same event answers `duplicate: true`; a wrong signature answers 400.
4. A Pro event unlocks every deal and sets the tier to `pro`; `customer.subscription.deleted` sets
   it back to `free` while access runs to the paid-through date.

Observability: every export logs `{"event":"export","orgId":…,"dealId":…,"versionId":…,"kind":"pdf","bytes":…,"ms":…}`;
the render service logs `render` with the version id and time; Sentry is initialised on both when
`SENTRY_DSN` is set. Deployment steps, the backup workflow and the restore-drill record are in
`docs/deploy.md`.
